# keripy decides whether a store is NEW by calling LMDBer.exists(name, base) without the headDirPath it was just handed (dbing.py:453 in 2.0.0-dev6), so newness is judged against the HOST's default keri home (/usr/local/var/keri/..., ~/.keri/...) rather than against the path being opened. Consequence for tests: a store created at a tmp_path head under a name that also exists under the host's real keri home is treated as pre-existing, so its version is never stamped, and the very next reopen raises DatabaseError('Database migrations must be run. DB version None'). Hit on 2026-09-11 with the name 'probe' — /usr/local/var/keri/db/probe exists on this box (44 such dirs, left by other repos' runs), so the test failed here and would have passed in CI. Mitigation in place: distinctive store names in tests/test_runner.py. Worth an upstream issue; also worth checking whether any other test in this repo uses a name generic enough to collide.
