# No real-keripy integration test for delegated tag inheritance (@4qrayq3j). reader._chain is unit-tested against a fake key-state store covering multi-level walks, unfollowed delegators, cycles and the depth guard, but nothing exercises it against a genuine delegated AID in a witness LMDB. Attempted and abandoned 2026-09-16: a delegated inception is not accepted by a bare witness even after the delegator anchors the seal in a rotation -- it lands in db.misfits (also ooes, pdes), because keripy 2.1 wants the delegation approval exchanged through the full delegation runtime (see tests/app/test_delegating.py, which stands up doers and a witness receipting loop). Options: (a) port that runtime into a fixture, which is heavy; (b) drive keripy's own delegation helpers directly if a lighter path exists; (c) accept the unit coverage and note the gap, which is what shipped. The risk is narrow -- the walk logic is covered and the only untested part is that state.di and state.b on a REAL delegated key state hold what the fake assumes -- but that assumption is exactly the kind tests/test_keripy_contract.py exists to pin, so a contract test over a real delegated state would be the cheap partial fix.
