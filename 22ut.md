# Decide whether a witness's AID list is an enumeration surface, and whether that constrains the control-plane read endpoints. Charles Lanahan (daidoji) raised it on WebOfTrust/kids#1 (2023-11-05) against a draft that had super watchers discovering every AID a witness serves: an adversary who can enumerate a witness network learns every AID in it, so the answer may need to be 'all AIDs the witness makes discoverable' rather than 'all AIDs it serves'. Daniel accepted the point at the time and it was never built. Two reasons this lands here. (1) It bears directly on /v1/witness/controller, which already over-reports (see tick 4pqt) and whose whole job is 'whom does this witness witness' -- if AID enumeration is a privacy surface then that endpoint is one, which sharpens the unauthenticated-read-surface problem in tick 3lda. (2) The same thread proposed the mirror-image surface: witnesses publishing which watchers poll them, so watcher reputation can be computed -- which enumerates watchers that may prefer not to be enumerated. Note the keri-bible has no coverage of witness/watcher-layer enumeration at all; its privacy material is entirely ACDC-disclosure-layer. Companion tick in bakobo/watcher covers the duplicity-notification half.
