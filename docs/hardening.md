# What has been hardened

A stock keripy witness is a single-threaded HTTP server with no notion of a slow, oversized or abusive client, and one of its routes will fetch any URL a stranger posts. This page lists what this repo does about that and about the rest of a witness's exposure: for each threat, the mitigation, what proves the mitigation is real, and what it leaves uncovered. The last column matters most. A protection whose limits nobody wrote down gets relied on past them.

Two layers are involved. The **image** ([`deploying.md`](deploying.md)) carries what holds wherever it runs. The **reference kit** ([`deploy/`](../deploy/README.md)) is the edge a public witness needs in front of the image, which you install on the host; Bakobo's own estate is configured separately and is not described here.

## The image

| Threat | Mitigation | Proven by | Not covered |
| --- | --- | --- | --- |
| A compromised witness process reaching beyond its data | Read-only root filesystem, every capability dropped, `no-new-privileges`, a 128-task process table against a measured peak of 14, and `/tmp` as a small noexec tmpfs ([what to run](deploying.md#what-to-run)) | The flags live once, in `witness.hardening.RUN_FLAGS`. Every image oracle and every pooled witness runs under them, one test reads the result from inside the running container, and `tests/test_hardening.py` holds the docs to the constant | The data volume is writable and holds the witness's signing key **unencrypted**. The host's uid boundary protects it; a passcode would have to live on the same host and would protect nothing |
| A substituted or tampered image | Every digest built from `main` or a release tag is signed keyless with cosign, with SLSA provenance and an SPDX SBOM bound to it. The documented `cosign verify` accepts only `image.yml` on a release tag ([verify](deploying.md#verify-before-you-run-a-digest)) | `tests/test_supply_chain.py` holds the command to its two pins. The signing job verifies its own signature, so a release that does not verify fails its build | Nothing enforces verification on the deploying host. Pull requests are never signed |
| Control-plane data read by a stranger | Six nouns need an RFC 9421 signature from a named operator, and the change feed needs a separately named watcher. With none named, they refuse everyone ([authentication](control-plane.md#authentication)) | `tests/test_control_auth.py`, `tests/test_change_feed.py` | A request signed for one witness can be replayed to a sibling that names the same operator, within `--max-age` (60 s), unless `--authority` is set. This is accepted (`@34sgjmxr`) |
| A query flood parking entries in the query-not-found escrow, which keripy sweeps on every loop pass | `--escrow-interval` paces the sweep to once a second instead of 32 times; `--escrow-timeout` shortens the window to 60 s from keripy's 300 | Measured, not inferred: at 5 req/s of attack, median loop lag falls from 0.079 s to zero. Curve and harness in [`escrow-load.md`](escrow-load.md), oracle `tests/test_escrow_load.py` behind `WITNESS_LOAD` | Many sources at a low rate each. `/v1/witness/health` stays `ok` through it by design; alert on `witness.loop.lag` instead ([which metrics](deploying.md#health-and-alerting)) |
| A wedged loop that looks healthy | Health reports `degraded` and names the doer once one has held the loop past five seconds | `tests/test_reader.py` | A loop that is slow rather than stuck. That is a metric's job |
| Unbounded or unvetted input at any boundary | Every boundary read goes through a named door that bounds size, then shape, then meaning | `tests/test_doors.py`, an AST census that fails on a read outside a door or an exemption without a written reason | An exemption whose reason stops being true. The census carries a `LAST_REVIEWED` date because only a person catches that |
| Losing the witness's identity | `witness backup` takes a transactionally consistent snapshot of every keripy store, keystore included, while the witness keeps receipting ([backing up](deploying.md#backing-up)) | `tests/test_image_upgrade.py` backs up, destroys the volume, restores, and requires the restored witness to receipt a **new** event | The change log is not backed up, so watchers re-pin and resync after a restore. A keripy migration is a one-way door, and the migration itself is not exercised by any test ([upgrading](deploying.md#upgrading)) |
| Splitting the two processes across containers | One container, one PID namespace, one supervisor. LMDB's reader locks assume a shared PID namespace ([why](deploying.md#three-things-that-are-silent-when-wrong)) | Documented rather than enforced. `tests/test_supervisor.py` covers the supervisor's asymmetric failure policy | Nothing stops a deployment from splitting them anyway |

## The reference kit

| Threat | Mitigation | Proven by | Not covered |
| --- | --- | --- | --- |
| A published port slipping past the host firewall | Both ports publish to `127.0.0.1`. Docker's published-port rules bypass `INPUT`, so a world-published port would escape nftables entirely | `tests/test_deploy_kit.py`; `ss -ltn` in [verify](../deploy/README.md#verify-each-protection-is-live) | — |
| Slow, oversized or streamed requests tying up keripy's single thread | Caddy terminates TLS, applies 30-second read, write and upstream-header timeouts, buffers each whole request, and refuses bodies over 512KB with 413 | `tests/test_deploy_kit.py` reads the Caddyfile; `tests/test_deploy_proxy.py` runs it under a real Caddy, which CI installs and requires | A request that *declares* an oversized body is dialled through before Caddy refuses it, so the witness holds that connection for up to 30 s. Chunked bodies never reach it |
| Making the witness fetch arbitrary URLs | `/ext`, keripy's unauthenticated OOBI-resolution route, is answered 404 and never proxied | `tests/test_deploy_kit.py`; a curl in [verify](../deploy/README.md#verify-each-protection-is-live) | — |
| Reaching the control plane from outside | Caddy proxies only `GET /v1/witness/change` and `GET /v1/witness/identity`, for remote watchers, and answers every other `/v1/witness` path 404. Port 5633 stays on loopback; operators tunnel | `tests/test_deploy_proxy.py`, which also proves a watcher's signature survives the proxy (`@9y806dye`) | — |
| Connection floods | nftables, per source address, IPv4 and IPv6, on 80 and 443: at most 64 concurrent connections and 25 new a second after a burst of 60, dropped in the kernel | `tests/test_deploy_kit.py`; the flood commands in [verify](../deploy/README.md#verify-each-protection-is-live) | It bounds connections, not requests: one HTTP/2 connection carrying ten thousand requests passes. HTTP/3 over UDP is not limited |
| Sources that keep failing | fail2ban bans a peer for an hour after ten counted 4xx in ten minutes, doubling per repeat up to a day. KERI's `/oobi`, `/receipts` and `/query` are exempt, because a polling controller legitimately gets 4xx there | `tests/test_deploy_kit.py`; `fail2ban-regex` in [verify](../deploy/README.md#verify-each-protection-is-live) | It needs Caddy as the TCP edge: behind a load balancer or CDN every ban lands on the proxy. It does not see abuse that succeeds |
| The edge's own admin surface | Caddy's admin API is on a unix socket rather than `localhost:2019` | `tests/test_deploy_kit.py` | — |
| CESR-over-TCP | Port 5632 is not published (`@m4c35y`) | `tests/test_deploy_kit.py` | — |

## What is not hardened

There is **no request rate limit**. Caddy would need a third-party plugin, and the kit leaves request volume to nftables and fail2ban, which bound connections and failures but not a stream of successful requests. KERI's own unauthenticated routes, `/oobi`, `/receipts` and `/query`, are open by protocol and stay open, which is why the escrow pacing above exists.

The [Registrar](registrar.md) is a separate process with its own defences against untrusted callbacks; they are described there.
