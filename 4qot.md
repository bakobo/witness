# Witness-side pull repair (post-summit plan item witness-repair; decided with Daniel 2026-10-15 in utah-keri-adoption's concurrency-design interview, recorded at ~/code/bakobo/utah-keri-adoption/design/concurrency-design/interview.md 'Raised by Daniel'). GOAL: a witness that holds an accepted event for an AID it is DESIGNATED for, but fewer receipts than len(b), repairs itself without the controller, so a missed propagation or downtime during the event does not leave it unable to serve that AID's OOBI (keripy refuses OOBIs for an event it does not consider fully witnessed; see heti witnessing._propagate's docstring). MECHANISM, no new wire protocol: after a configurable age T, query the co-witnesses named in that event's own b for the KEL replay (standard qry, route logs; clonePreIter attaches each event's wigs, basing.py:1726 at keripy 8573aa57) and feed the reply through the witness's own Kevery. Verified 2026-10-15 that keripy merges late witness signatures on a DUPLICATE event: eventing.py:4365 and :4452 at 8573aa57 ('this allows late arriving witness receipts'), verifying each wig, so a lying peer can only withhold, never inject. Co-witness endpoints: the controller's inception propagation already carries agenting.schemes for the other witnesses (heti witnessing._propagate), so a witness normally knows how to reach them; an unknown endpoint is a skip, not a failure. WHAT TO INDEX: do not scan every KEL. The change feed (@6y23f6w2, src/witness/changehook.py) sees every accepted event, so it can enqueue (pre, sn, said, accepted_at) for any event short of full tally and dequeue when wigs reach len(b). Run as an appended doer on the witness's own timer, paced like the escrow sweeps (@zj3h2pzh, src/witness/escrows.py) with per-peer backoff and a global rate cap. REFUSED, with reason: pulling in response to an INBOUND query for an AID the witness does not hold. Queries are unauthenticated at the public port and docs/escrow-load.md:16 already measured that unknown-AID queries park qnfs entries and lag the loop; fanning each out to peers turns that into amplification. Pull only for AIDs this witness is designated for, only on its own timer. SCOPE: works with any KERI witness as the peer (it uses standard messages), so it is not own-fleet-only; push gossip with SMT diffs stays out of scope and remains the ambitious option set aside earlier. PRIVACY: a repair query tells a co-witness which AIDs this witness serves, which the co-witness already knows from b, so no new enumeration (compare ~22ut). OPEN QUESTIONS for the item's interview: default T; whether a repaired witness should also push what it learned to the controller's mailbox; metrics (witness.repair.pending depth, witness.repair.fetched) beside the escrow-depth alarm. The controller-side half (heti re-propagating over long-lived per-witness lanes) is heti-parallel's job, not this item's.
